# Update Nova to a Minecraft version

Use this skill for a requested Minecraft/Paper version update in the Nova repository. Get the target version from the request; ask if it is missing. Preserve unrelated working-tree changes.

## Upgrade and verify

1. Inform yourself about the update and its changes by reading the corresponding article on minecraft.wiki and the "Minecraft changes" section in Fabric's update guide. Reference relevant wiki or update guide sections in your final report later.
2. Update the Paper version in `gradle/libs.versions.toml` (the repository's version catalog). Update the exact supported Minecraft version range in `nova/src/main/kotlin/xyz/xenondevs/nova/NovaBootstrapper.kt`; otherwise Nova will reject the new server at startup.
3. Recompile with Gradle and repeat until compilation succeeds. Inspect each error using the IDE index and the target version's Paper-patched server sources. If those sources are unavailable, run `gradle _oriInstall` and retry. For a likely Mojang/Paper rename, compare declarations and implementations before replacing the call; change it automatically only when the behavior is equivalent. If behavior, lifecycle, data format, or intent changed, explain the finding and ask the user how Nova should adapt before implementing that part. Continue independent fixes while waiting. If an update happens early in the release cycle, Paper may not include larger patches like Moonrise yet. Do not remove code that uses those but instead comment it out, add relevant TODO comments, and note it in the final report.
4. Run `gradle nova:_oriMixin` after compilation succeeds. Investigate and fix Mixin application failures against Paper-patched server sources, then rerun it.
5. Once Mixins apply, try starting the target server with `runOrigamiServer`. Prefer an existing IDE run configuration when it points to the user's development server, and ask permission before running any IDE configuration. If no suitable configuration exists, use the Gradle task and report which server directory it uses. Check startup logs for Nova initialization and resource pack failures; fix version-update issues and reverify the affected stage.
6. Perform the fixed manual review below even if compilation and startup pass. Compare with the target version's server implementation or vanilla assets as appropriate. Add a new review entry only when a concrete version-sensitive mapping or invariant is found; do not rescan the entire project on each future update.
7. Go over the aspects that require manual review as described below.
8. Use git diff to look at the changes you made. Revert unnecessary changes.
9. Create the final overview as described below.

## Fixed manual review

In no particular order:

- `nova/src/main/kotlin/xyz/xenondevs/nova/world/block/BlockUpdateFlags.kt`: compare all exposed flags and presets with the target `Block` update flags, including new flags and changed meanings.
- `nova/src/main/kotlin/xyz/xenondevs/nova/world/block/sound/SoundGroup.kt`: compare exposed groups with `SoundType` and add new groups that Nova should expose.
- `nova-packet-entity/src/main/kotlin/xyz/xenondevs/nova/packetentity/DefaultValues.kt`: compare every hand-maintained default with target entity constructors and synced data definitions. New required values generally cause compile errors; changed existing defaults may not.
- `nova/src/main/kotlin/xyz/xenondevs/nova/world/block/tileentity/vanilla/VanillaTileEntity.kt`: check whether new vanilla block entities need wrappers for Nova's vanilla container/network behavior.
- `nova-network/src/main/kotlin/xyz/xenondevs/nova/network/event/`: update packet events to match their packets. Breaking changes allowed. The events' properties should match the packets. It is expected that new packets will be records and thus automatically generated by ksp. If a packet has turned into a record, you can remove the duplicate manual packet event implementation.
- `@Serializable` classes that mirror resource pack contents, data components, etc. Add new and missing functionality, mirror changes, etc.

## Minecraft assets not available yet

`nova/src/main/kotlin/xyz/xenondevs/nova/resources/builder/ResourcePackBuilder.kt` downloads assets from https://github.com/InventivetalentDev/minecraft-assets. If it lacks the exact target version, check which nearby version actually exists before temporarily hardcoding the downloader's source version. Mark the temporary override with a TODO comment.

## Final overview

Summarize the version-related changes actually encountered, ordered by their impact on Nova rather than by file or compilation order. For each, explain what changed in Minecraft or Paper and how Nova was updated in response. Group straightforward renames; give more detail to behavior changes and decisions made with the user.

Close with the compilation, `nova:_oriMixin`, and server startup results, plus any unresolved issue or temporary workaround. Do not turn the manual-review checklist into a report of unchanged files.
